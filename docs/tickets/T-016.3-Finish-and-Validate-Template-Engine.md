---

# 4. Pflicht / optional / bedingt

Template-Punkte müssen unterscheiden können:

- Pflicht
- optional
- bedingt

Bedingte Punkte nur aktivieren, wenn der zugehörige Kontext zutrifft.

Beispiele:

Statik nur falls erforderlich.

Sondernutzung nur falls öffentlicher Raum betroffen.

Kran nur falls Kran erforderlich.

---

# 5. Blocker

Blocker unabhängig vom Prozentfortschritt behandeln.

Beispiel:

99 % Vorbereitung

aber

Sondernutzung erforderlich und fehlt

=

nicht freigabebereit.

Blocker Resolver prüfen.

Keine automatische sicherheitskritische Freigabe.

---

# 6. React-Integration

Sehr wichtig:

Prüfen, ob der Activity Workspace die Template Engine tatsächlich verwendet.

Die Template Engine darf nicht nur als ungenutzte Library existieren.

Bestehende hart codierte Formularkonfiguration soweit sinnvoll auf die Template-Ausgabe umstellen.

Keine großen `if (type === "...")`-Sonderlogiken in React neu einführen.

Bestehende T-016.2-Daten müssen kompatibel bleiben.

# Validierung

Mindestens prüfen:

1. Registry lädt.
2. Resolver erzeugt ein Template.
3. mehrere Overlays funktionieren.
4. Deduplizierung funktioniert.
5. bedingte Punkte funktionieren.
6. Blocker funktionieren.
7. Activity Workspace verwendet die Engine tatsächlich.
8. bestehende Activity ohne Template funktioniert.
9. Reload verliert keine Activity-Daten.

npm run build
git diff --check
