# T-015.1 – Projektarbeitsplatz

## Ziel

Sobald ein Projekt geöffnet wird, arbeitet der Bauleiter nahezu vollständig innerhalb eines zentralen Projektarbeitsplatzes.

Der Projektarbeitsplatz soll nicht nur Informationen anzeigen, sondern die vollständige operative Projektakte strukturiert zugänglich machen.

Keine neue Fachlogik.

Keine Datenmigration.

Bestehende Daten und Activities weiterverwenden.

---

# Grundprinzip

Ein Projekt besitzt genau einen Projektarbeitsplatz.

Alle projektbezogenen Informationen werden dort gebündelt.

Der Nutzer soll nicht ständig zwischen verschiedenen Hauptbereichen wechseln müssen.

---

# Projektkopf

Oben ein klarer, kompakter Projektkopf.

Mindestens anzeigen:

- Projektname
- Baustellenadresse
- Kunde
- Bauherr falls vorhanden
- Ansprechpartner
- Bauleiter
- Vorarbeiter
- Kolonne
- aktueller Projektstatus
- Projektphase
- Vorbereitungsgrad
- nächster Termin
- letzte Aktivität
- offene Punkte

Der Lebenszyklusstatus soll deutlich sichtbar sein.

Beispiele:

- Einsatzvorbereitung
- Aufbau
- Nutzung
- Umbau
- Abbau
- Abrechnung
- abgeschlossen
- archiviert

Status optisch klar unterscheiden.

---

# Projektfortschritt

Im Kopf oder direkt darunter einen kompakten Projektfortschritt vorbereiten.

Beispiel:

Angebot
✓

Einsatzvorbereitung
✓

Projekt
● Aufbau

Abrechnung
○

Archiv
○

Keine neue automatische Phasenlogik implementieren.

Bestehende Statusinformationen verwenden.

---

# Tabs

Unterhalb des Projektkopfes feste Tabs:

1. Übersicht
2. Aktivitäten
3. Dokumente
4. Fotos
5. Rechnungen
6. Termine
7. Material
8. Kolonne
9. KI
10. Verlauf

Tabs sollen innerhalb derselben Projektseite funktionieren.

Keine unnötigen Seitenwechsel.

Aktiver Tab eindeutig sichtbar.

Responsive berücksichtigen.

Auf Mobile dürfen Tabs horizontal scrollbar oder kompakt dargestellt werden.

---

# Übersicht

Die Übersicht ist der operative Projektstatus.

Mindestens anzeigen:

- aktueller Status
- Vorbereitungsgrad
- heute relevante Aufgaben
- kritische Punkte
- offene Fragen
- offene Freigaben
- nächster Termin
- letzte Aktivität
- letzte Fotos
- letzte Dokumente
- Materialstatus
- Kolonnenstatus
- kaufmännischer Kurzstatus
- offene Rechnungen / Nachträge

Bestehende Project-Cockpit-Daten wiederverwenden.

Keine Dummy-Daten.

---

# Aktivitäten

Bestehende Activity Engine verwenden.

Alle projektbezogenen Activities anzeigen.

Mindestens filterbar beziehungsweise strukturell vorbereiten nach:

- offen
- heute
- kritisch
- erledigt
- Kommunikation
- Montage
- Aufmaß
- Kontrolle
- Material
- Nachtrag
- Rechnung
- Telefonat

Keine zweite Aufgabenlogik bauen.

Activity bleibt die einzige operative Prozesslogik.

---

# Dokumente

Projektbezogene Dokumente zentral sichtbar machen.

Mindestens vorbereiten:

- Angebot
- Pläne
- Statik
- Sondernutzung
- Montageanweisung
- Gefährdungsbeurteilung
- Prüfprotokolle
- Lieferscheine
- Freigaben
- sonstige PDFs

Bestehende Dokumentdaten verwenden.

Keine Dokumentengenerierung implementieren.

---

# Fotos

Projektgalerie.

Alle projektbezogenen Bilder aus:

- Activities
- Baustellenbesuchen
- vorhandenen Projektfotos

zusammenführen.

Keine Duplikate.

Mindestens anzeigen:

- Vorschau
- Datum
- Quelle
- Activity / Baustellenbesuch
- Beschreibung falls vorhanden

---

# Rechnungen

Projektbezogene kaufmännische Sicht.

Mindestens anzeigen / vorbereiten:

- Abschlagsrechnungen
- Schlussrechnung
- Nachträge
- Zahlungsstatus
- letzte Abschlagsrechnung
- offene Forderungen
- Mietbeginn
- Abmeldedatum
- abrechenbare Mietmengen

Keine vollständige Rechnungsberechnung implementieren.

---

# Termine

Projektbezogene Termine.

Mindestens vorbereiten:

- Montage
- Umbau
- Abbau
- Aufmaß
- Kontrolle
- Besprechung
- Jour Fix
- Rückruf
- sonstige projektbezogene Termine

Später an persönlichen Kalender anbinden.

Noch keine doppelte Termin-Datenhaltung erzeugen.

---

# Material

Projektbezogene Materialsicht.

Mindestens vorbereiten:

- geplant
- reserviert
- geliefert
- fehlt
- nachbestellt
- abzuholen

Bestehende Materialdaten verwenden, falls vorhanden.

Keine vollständige Materialwirtschaft implementieren.

---

# Kolonne

Projektbezogene Personal- und Ressourcensicht.

Mindestens vorbereiten:

- zugewiesene Kolonne
- Vorarbeiter
- Mitarbeiter
- Fahrzeuge
- Geräte
- geplanter Einsatzzeitraum

Keine vollständige Disposition implementieren.

---

# KI

Projektbezogener Assistenzbereich vorbereiten.

Keine echte KI-Funktion in diesem Ticket implementieren.

Zielbild:

Die KI arbeitet ausschließlich im Kontext dieses Projekts.

Spätere Fragen:

- Welche Unterlagen fehlen?
- Welche offenen Arbeiten existieren?
- Wann wurde zuletzt telefoniert?
- Welche Nachträge sind offen?
- Wann ist der nächste Termin?
- Wie ist der Projektstatus?

Nur hochwertiger Grundzustand / Platzhalter.

Keine Dummy-Antworten.

---

# Verlauf

Chronologische Projekthistorie.

Bestehende Informationen verwenden:

- Activities
- Baustellenbesuche
- Notizen
- Statusänderungen soweit vorhanden
- Dokumente
- Fotos
- Kommunikation soweit vorhanden

Keine parallele Timeline-Datenhaltung bauen.

---

# Sticky Verhalten

Desktop:

- Projektkopf soll beim Scrollen kompakt erreichbar bleiben
- Tabnavigation soll beim Scrollen sichtbar bleiben

Nicht zu viel Bildschirmhöhe blockieren.

Keine störenden Effekte.

---

# Navigation

Die globale Hauptnavigation aus T-014 bleibt unverändert.

Der Projektarbeitsplatz befindet sich innerhalb von "Projekte".

Keine weiteren Hauptmenüpunkte ergänzen.

---

# Rückwärtskompatibilität

Sehr wichtig:

- bestehende Projekte erhalten
- bestehende Activities erhalten
- bestehende Baustellenbesuche erhalten
- Bilder erhalten
- Dokumente erhalten
- Angebotsdaten erhalten
- Project-Cockpit-Daten erhalten
- LocalStorage-Daten weiter lesbar

Keine Migration, sofern nicht zwingend notwendig.

---

# Nicht Bestandteil

- keine neue Activity Engine
- keine echte KI
- keine Outlookintegration
- keine Materialdisposition
- keine Kolonnendisposition
- keine neue Rechnungsengine
- keine Dokumentengenerierung
- keine neuen Dummy-Daten

---

# Validierung

Manuell prüfen:

1. Projekt öffnen.
2. Projektkopf vollständig sichtbar.
3. Lebenszyklusstatus sofort erkennbar.
4. Alle Tabs erreichbar.
5. Tabwechsel ohne unnötigen Seitenwechsel.
6. bestehende Activities sichtbar.
7. bestehende Bilder sichtbar.
8. bestehende Baustellenbesuche weiterhin nutzbar.
9. Angebot weiterhin auffindbar.
10. Rechnungsinformationen weiterhin auffindbar.
11. Reload erhält alle Daten.
12. Desktop funktioniert.
13. Mobile funktioniert.
14. Sticky Tabs funktionieren ohne Layoutfehler.

Technisch:

- npm run lint
- npm run build
- git diff --check

Nicht committen.
Nicht pushen.

Nach Abschluss auflisten:

- geänderte Dateien
- neue Dateien
- wiederverwendete bestehende Datenquellen
- offene Punkte
