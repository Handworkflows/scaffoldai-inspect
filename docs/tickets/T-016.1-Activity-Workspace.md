# T-016.1 – Activity Workspace

## Ziel

Activities werden zum zentralen Arbeitsbereich von ScaffoldAI.

Jede Activity besitzt einen eigenen Workspace und ist kein einfaches Formular mehr.

---

## Anforderungen

Die Detailansicht einer Activity soll vollständig neu aufgebaut werden.

### Header

Anzeigen:

- Activity-Typ
- Status
- Priorität
- Projekt
- Baustelle
- Verantwortlicher
- Fälligkeitsdatum

Header bleibt beim Scrollen sichtbar.

---

### Tabs

- Übersicht
- Checkliste
- Fotos
- Dokumente
- Kommentare
- Verlauf

Nur ein Tab gleichzeitig sichtbar.

---

### Übersicht

Zeigen:

- Beschreibung
- Status
- Verantwortlicher
- Projekt
- Baustelle
- Fälligkeit
- Offene Punkte

---

### Checkliste

Vorbereitung für spätere dynamische Checklisten.

Checkboxen müssen bereits funktionieren.

---

### Fotos

Vorhandene Fotos anzeigen.

Neue Fotos können vorbereitet werden.

Noch keine neue Datenhaltung.

---

### Dokumente

Bereits vorhandene Anhänge anzeigen.

Keine neue Speicherung.

---

### Kommentare

Vorbereitung für Activity-Kommunikation.

Nur bestehende Daten verwenden.

---

### Verlauf

Zeitlicher Verlauf.

Statusänderungen

Erstellt

Aktualisiert

Abgeschlossen

---

### Rechte Kontextspalte

Tababhängig.

Zeigt:

- wichtige Hinweise
- offene Punkte
- Fristen
- Status

---

## Nicht umsetzen

Kein KI-Chat

Keine neue Datenbank

Keine Migration

Keine neuen LocalStorage-Keys

Keine API

---

## Wiederverwenden

Activity Engine

Project Core

bestehende Activity-Daten

bestehende Fotos

bestehende Dokumente

bestehende Kommentare

---

## Akzeptanzkriterien

- kompletter Activity-Workspace
- Sticky Header
- Sticky Tabs
- responsive
- Desktop + Mobile
- npm run lint
- npm run build
- git diff --check
- kein Commit
- kein Push
